# 记忆系统

## 做了什么

虾小丘的记忆系统分三层，实现从短期到长期的记忆持久化：

| 层级 | 存储位置 | 内容 | 生命周期 |
|------|---------|------|---------|
| **短期记忆** | memory/YYYY-MM-DD.md | 每天做了什么、对话摘要、新学到的信息 | 按天积累 |
| **长期记忆** | MEMORY.md | 提炼后的核心知识、行为规范、已分析问题、配置信息 | 持续更新 |
| **向量记忆** | ChromaDB (195 文档块) | 所有记忆的语义索引，支持自然语言搜索 | 增量同步 |

## 核心思路

### 三层记忆的工作方式

```
每次会话启动
  → 读取 SOUL.md + USER.md（身份和行为）
  → 读取今天的 memory/YYYY-MM-DD.md + 昨天的（最近上下文）
  → 如果是主会话（直接和用户聊天），额外读取 MEMORY.md（长期记忆）

每次用户说了值得记住的事
  → 追加到今天的 daily memory
  → 如果是重要的长期知识，同步写入 MEMORY.md

每隔 2-3 天（心跳维护）
  → 回顾最近几天的 daily memory
  → 提炼重要信息更新到 MEMORY.md
  → 删除过时信息
  → 运行 migrate.py 更新向量索引
```

### 记忆写入原则

- **短期→长期**：不是每次聊天都写 MEMORY.md，只有重要的决策、教训、配置变化才写
- **文件 > 脑中**：AI 不信任「我记住了」，必须写文件。每个会话都是从文件加载，不依赖上次会话的状态
- **增量索引**：写了新 daily memory 后运行 `migrate.py`，已存在的文档块不会重复添加

### 心跳维护机制

每 30 分钟 OpenClaw 会发送一次心跳，AI 可以趁机做维护工作：

**轻量检查**（大部分心跳）：
- 确认 Ollama 还在运行，挂了就 `ollama serve &`
- 检查是否有重要邮件/日历
- 如果没有需要处理的，回复 `HEARTBEAT_OK`

**深度维护**（2-3 天一次）：
- 回顾 daily memory，更新 MEMORY.md
- 清理过时的配置信息
- 运行 `migrate.py` 同步向量索引

## 复用指南

### 记忆系统设计模式

**三层模型通用**，适用于任何需要长期记忆的 AI 助手：

```
短期层：[memory/YYYY-MM-DD.md] 每天自动追加
   ↓ 定期提炼
长期层：[MEMORY.md] 只存值得长期保留的
   ↓ 自动索引
搜索层：[向量数据库] 支持语义搜索
```

**文件结构模板**：
```
workspace/
├── MEMORY.md              # 长期记忆
├── memory/
│   ├── YYYY-MM-DD.md      # 每天的短期记忆
│   └── heartbeat-state.json  # 心跳状态跟踪
└── vector_db/
    ├── migrate.py          # 索引更新脚本
    ├── query.py            # 语义搜索脚本
    └── chroma_data/        # 向量数据持久化
```

### 短期记忆模板

```markdown
# YYYY-MM-DD

## 做了什么
- [简要记录今天的交互和操作]

## 新学到的
- [今天学到的新知识/新配置]

## 待跟进
- [还未解决的问题]
```

### 长期记忆模板

```markdown
# MEMORY.md

## 用户
- [用户信息、偏好、习惯]

## 基础设施
- [服务器、设备、账号信息（不含密码）]

## 已分析问题
- [问题编号：描述 → 根因 → 结论]

## 行为规范
- [核心规则]
```

### 心跳维护模板

**心跳检查清单**（写在 HEARTBEAT.md 里）：
```markdown
# 心跳检查

每次心跳：
- [ ] Ollama 服务是否存活
- [ ] 磁盘空间是否足够
- [ ] 重要日历/邮件

深度维护（标记 [deep] 项，2-3天执行一次）：
- [deep] 审查最近 daily memory，更新 MEMORY.md
- [deep] 运行向量索引同步
```
