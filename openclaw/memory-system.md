# 记忆系统

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## 做了什么

虾小丘的记忆系统分三层，实现从短期到长期的记忆持久化：

| 层级 | 存储位置 | 内容 | 生命周期 |
|------|---------|------|---------|
| **短期记忆** | `memory/YYYY-MM-DD.md` | 每天做了什么、对话摘要、新学到的信息 | 按天积累 |
| **长期记忆** | `MEMORY.md` | 提炼后的核心知识、行为规范、已分析问题 | 持续更新 |
| **向量记忆** | ChromaDB（195 文档块） | 所有记忆的语义索引，支持自然语言搜索 | 增量同步 |

───

## 核心思路

### 会话启动时的加载顺序

```
1. SOUL.md + USER.md（身份和行为）
2. memory/YYYY-MM-DD.md（今天）+ memory/YYYY-MM-DD.md（昨天）
3. 如果是主会话（直接和用户聊天）→ 额外加载 MEMORY.md
```

### 三层记忆的协作方式

| 时机 | 做什么 |
|------|--------|
| 用户说了值得记住的事 | 追加到今天的 daily memory |
| 有重要知识/决策/教训 | 同步写入 MEMORY.md（不常写，只存精华） |
| 写了新 daily memory 后 | 运行 `migrate.py` 增量更新向量索引 |

> ⚠️ AI 不信任「我记住了」，必须写文件。每个会话从文件加载，不依赖上次会话状态。

───

### 心跳维护机制

> 💡 每 30 分钟 OpenClaw 发送一次心跳，AI 趁机做维护。

**轻量检查**（大部分心跳）：

| 检查项 | 操作 |
|--------|------|
| Ollama 存活 | `curl -s http://127.0.0.1:11434`，挂了就 `ollama serve &` |
| 无紧急事项 | 回复 `HEARTBEAT_OK` |

**深度维护**（2-3 天一次）：

| 操作 | 说明 |
|------|------|
| 回顾 daily memory | 提炼重要信息更新到 MEMORY.md |
| 清理过时信息 | 删除不再相关的配置和记录 |
| 同步向量索引 | 运行 `migrate.py` |

## 🔄 复用指南

### 三层记忆模型

> 💡 适用于任何需要长期记忆的 AI 助手。

```
短期层：[memory/YYYY-MM-DD.md] 每天自动追加
   ↓ 定期提炼
长期层：[MEMORY.md] 只存值得长期保留的
   ↓ 自动索引
搜索层：[向量数据库] 支持语义搜索
```

### 文件结构模板

```
workspace/
├── MEMORY.md              # 长期记忆
├── memory/
│   ├── YYYY-MM-DD.md      # 每天的短期记忆
│   └── heartbeat-state.json  # 心跳状态跟踪
└── vector_db/
    ├── migrate.py          # 索引更新脚本
    ├── query.py            # 语义搜索脚本
    └── chroma_data/        # 向量数据持久化
```

### 短期记忆模板

```markdown
# YYYY-MM-DD

## 做了什么
- [简要记录今天的交互和操作]

## 新学到的
- [今天学到的新知识/新配置]

## 待跟进
- [还未解决的问题]
```

### 长期记忆模板

```markdown
# MEMORY.md

## 用户
- [用户信息、偏好、习惯]

## 基础设施
- [服务器、设备信息]

## 已分析问题
- [问题编号：描述 → 根因 → 结论]

## 行为规范
- [核心规则]
```

### 心跳维护模板（写在 HEARTBEAT.md）

```markdown
# 心跳检查

每次心跳：
- [ ] Ollama 服务是否存活
- [ ] 磁盘空间是否足够
- [ ] 重要日历/邮件

深度维护（标记 [deep] 项，2-3天执行一次）：
- [deep] 审查最近 daily memory，更新 MEMORY.md
- [deep] 运行向量索引同步
```
