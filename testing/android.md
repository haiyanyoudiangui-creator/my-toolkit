## uiautomator2

> 💡 Python 封装的 Android UI 自动化库，通过 ADB 控制设备上的屏幕操作。

───

### 在 kaiboer 项目中的用法

#### 📋 绕过开机引导

| 步骤 | 做什么 |
|------|--------|
| 1 | 自动找到 **跳过/下一步/完成** 等按钮并点击 |
| 2 | 处理多页面引导流程，每页**等待并检查**元素出现 |
| 3 | 设置**超时和回退**机制，防止某个页面卡住整条流程 |
| 4 | 引导完成后关闭功能设置提示弹窗，最终确认进入桌面 |

#### 📋 WiFi 连接

| 步骤 | 做什么 |
|------|--------|
| 1 | 打开 WiFi 设置界面 |
| 2 | 在可用网络列表中**滚动**找到目标 SSID |
| 3 | 输入密码并连接 |
| 4 | 验证分配到的 IP 地址，确认连接成功 |

> ⚠️ 备选方案：当 UI 操作失败时，回退到 `cmd wifi` 命令连接。

#### 📋 应用安装与生命周期

| 步骤 | 方法 |
|------|------|
| **启动** | 通过 monkey 命令冷启动 app（不需要知道具体 activity 名） |
| **验证** | 监听当前前台包名变化判断 app 是否成功启动 |
| **退出** | 在应用内找到退出/关闭/返回按钮并点击 |
| **确认** | 检测应用是否回到桌面 |

#### 📋 播放器控制

| 方式 | 操作 |
|------|------|
| **Intent 直接传参** | 直接把本地音频文件路径传给 KBEPlayer 播放（无需手动操作播放器界面） |
| **Broadcast 控制** | 通过系统广播发 STOP/PLAY 指令控制播放 |
| **验证** | 检查播放状态日志确认音频真实在输出 |

#### 📋 UI 全量遍历

> 💡 逐页 dump XML 元素层级 → DFS 递归探索每个子页面 → 生成结构化快照索引。

| 步骤 | 做什么 |
|------|--------|
| 1 | 逐页 dump 当前屏幕的 XML 元素层级 |
| 2 | 找到所有**可点击**和**可滚动**的元素 |
| 3 | 用**深度优先搜索**递归进入每个子页面 |
| 4 | 每个页面生成**唯一签名**避免重复 |
| 5 | 最终输出结构化页面快照索引，记录每个页面的元素列表和可达路径 |

## ADB（通过 subprocess 调用）

> 💡 Android Debug Bridge，与安卓设备通信的命令行工具。

───

### 在 kaiboer 项目中的用法

#### 📋 设备管理

| 操作 | 作用 |
|------|------|
| 重启、恢复出厂设置 | 测试环境重置 |
| 等待启动完成 | 检查 `sys.boot_completed` 和包管理器就绪 |
| 连接切换 | USB 优先，USB 断开后自动切到网络 ADB |

#### 📋 系统信息采集

| 信息 | 命令 |
|------|------|
| 设备型号和 Android 版本号 | `adb shell getprop` |
| WiFi 接口 IP 地址 | `adb shell ip addr show wlan0` |

#### 📋 进程管理

| 操作 | 命令 |
|------|------|
| 强制杀进程 | `am force-stop {package}` |
| 验证应用已安装 | `pm list packages` |
| 检查系统属性 | `getprop` |

#### 📋 兜底方案

> ⚠️ uiautomator2 的 click 操作有时返回成功但实际未生效。

| 场景 | 兜底 |
|------|------|
| click 返回成功但没生效 | `adb input tap x y` |
| 无法定位到元素 | 手动传入坐标点击 |

## 🔄 复用指南

### 1. 开机引导跳过通用流程

> 💡 不是对特定页面写死点击逻辑，而是构建一个 **等待→检查→点击→兜底** 的状态机。

| 步骤 | 做什么 |
|------|--------|
| 1 | 检测当前是否在引导页面（通过特定文本或 package 判断） |
| 2 | 找到可点击的跳过/下一步/同意/完成按钮 |
| 3 | 点击后等待新页面出现，超时则重试 |
| 4 | 如果 UI 操作失败，回退到 `adb shell input tap x y` |
| 5 | 引导循环直到进入桌面（package = launcher） |

| 需要改 | 不需要动 |
|---------|---------|
| 目标 package 名、各页面按钮文本、adb input 坐标 | 整个状态机流程 |

### 2. 应用启动验证模式

> 💡 不依赖知道 activity 名，用 monkey 冷启动 + 包名监听判断成功。

```python
# 启动
device.shell(["monkey", "-p", package_name, "-c", "android.intent.category.LAUNCHER", "1"])
# 验证
current = device.app_current()
assert package_name == current['package']
# 退出
device.shell(["am", "force-stop", package_name])
```

**新项目**只需换 `package_name` 和等待时间。

### 3. UI 全量遍历 DFS 模式

> 💡 dump 当前页面 XML → 找到所有可点击元素 → 逐个点击 → 回退 → 换下一个。

| 步骤 | 做什么 |
|------|--------|
| 1 | `dump_hierarchy()` 获取当前页面 XML |
| 2 | 解析所有 `clickable=true` 的节点 |
| 3 | 给每个页面生成签名（节点文本+class 哈希），去重 |
| 4 | 深度优先：点一个元素 → 递归探索新页面 → 回退 → 点下一个 |
| 5 | 输出结构化索引：页面签名、路径、元素列表 |

| 需要改 | 不需要动 |
|---------|---------|
| 目标 package 名和模块定义（哪些页面属于哪个模块） | DFS 框架、签名生成、去重逻辑 |

### 4. ADB 兜底设计哲学

> 💡 uiautomator2 是主方案，adb 是备选。**每一步操作都应有 fallback**。

| 主方案 | 兜底 |
|--------|------|
| `(x, y).click()` | `adb shell input tap x y` |
| 找元素失败 | `dump_hierarchy()` 打印所有可见文本，辅助定位 |
| 连不上设备 | USB 自动切 IP 重试 |
